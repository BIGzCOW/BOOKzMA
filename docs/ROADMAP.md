# نقشهٔ راه BOOKzMA

اولویت فعلی: کیفیت، امنیت، سرعت و پایداری ربات و API موجود. وضعیت «ایده» اجازهٔ پیاده‌سازی نیست؛ برای شروع هر مورد، اول spec در `docs/specs/` بنویس و تأیید مالک را بگیر.

وضعیت‌ها: `ساخته‌شده`، `در حال کار`، `برنامه‌ریزی‌شده`، `ایده`، `کنار گذاشته`.

راهنمای ستون‌های ارزش/هزینه/منبع:

- **ارزش:** ا (بالا) · م (متوسط) · ک (کم)
- **هزینه:** S (کوچک: روزها) · M (متوسط: هفته‌ها) · L (بزرگ: ماه‌ها یا طراحی جدی)
- **منبع:** 👤 پیشنهاد مالک · 💡 پیشنهاد دستیار · 🔧 کار لازمِ زیرساختی
- هر جا به API تلگرام یا سرویس خارجی اشاره شده، قبل از طراحی با مستندات فعلی تلگرام تأیید شود.
- بخش «ترتیب پیشنهادی» و «ده ایدهٔ برتر» فقط پیشنهاد مالک‌اند و هنوز تأیید نهایی نشده‌اند.

الزامات امنیتی ثابت این بخش (برای همهٔ سطوح):

- دسترسی به Docker socket عملاً دسترسی root است؛ بنابراین W-03 هرگز با Docker socket داخل پنل ساخته نمی‌شود و از مسیر GitHub Actions یا یک سرویس deploy جدا انجام می‌شود.
- حذف داده، `down -v`، اجرای migration و دستور دلخواه **هرگز** از پنل انجام نمی‌شود؛ دستی و با تأیید مالک.
- پنل فقط پشت VPN/شبکهٔ خصوصی (WireGuard/Tailscale) یا حداقل reverse proxy با HTTPS و محدودیت IP.
- لاگین قوی + ۲FA؛ نشست کوتاه؛ محدودیت تلاش ورود؛ CSRF و هدرهای امنیتی؛ لاگ ممیزی؛ تأیید دومرحله‌ای برای اقدام حساس.
- پیش‌نیاز عملی: بکاپ آزموده‌شده (N-05) و امکان rollback قبل از هر دیپلوی خودکار.
