# مشخصات قابلیت: پشتیبانی دوطرفه و گزارش تیکت

## تأیید مالک

**۲۰۲۶-۱۱-۰۳:** کاربر و مدیر باید بتوانند در چند نوبت از داخل بات پیام ردوبدل کنند؛ مدیر بتواند کاربر را block/unblock کند و آمار فعالیت کتاب/تیکت در داشبورد مدیر دیده شود.

## رفتار

- کاربر در private chat متن یا media می‌فرستد؛ bot پیام را به مدیرهای `ADMIN_TELEGRAM_IDS` کپی می‌کند.
- مدیر با callback وابسته به ticket پاسخ می‌دهد؛ متن یا media پاسخ به کاربر کپی می‌شود و کاربر دکمه‌ی ادامه‌ی thread می‌گیرد.
- هر پاسخ دوباره به همان ticket باز وصل است؛ اطلاعات ticket از `ticket_id` خوانده و مالکیت/مجوز سمت سرور بررسی می‌شود.
- مدیر می‌تواند از همان پیام تیکت، user را block یا unblock کند. کاربر blockشده نمی‌تواند پیام جدید بفرستد.
- فقط ثبت موفق صفحه روز مطالعه/استریک را ثبت می‌کند. افزودن کتاب، تعیین تعداد صفحات و آرشیو استریک نمی‌سازد.

## داده و حریم خصوصی

- `support_tickets`: user، وضعیت و زمان ایجاد/به‌روزرسانی.
- `support_events`: ticket، actor ID، جهت پیام و زمان؛ متن، فایل، Telegram `file_id` یا payload پیام ذخیره نمی‌شود.
- `support_blocks`: user و مدیر انجام‌دهنده‌ی block؛ با حذف حساب cascade می‌شود.
- `user_books.page_count_set_at` فقط برای KPI تغییر تعداد صفحات استفاده می‌شود.
- حذف حساب، ticketها و metadata آن‌ها را cascade می‌کند.

## داشبورد مدیر

- کتاب‌های فعال/تمام‌شده/آرشیوشده، کتاب‌های افزوده/آرشیوشده در ۷ روز، تغییر تعداد صفحه، نشست‌های صفحه‌خوانی و صفحات ثبت‌شده.
- تیکت‌های باز/جدید، پیام‌های کاربر و پاسخ‌های مدیر در ۷ روز، و تعداد userهای blockشده.

## تست و deployment

- handler، مجوز admin، چندنوبتی، media-copy، block/unblock و عدم ثبت استریک در عملیات غیرمطالعه unit/flow test دارند.
- migration `0019` باید فقط روی PostgreSQL آزمایشی/محلی قبل از deploy آزموده شود؛ هرگز در این task روی production اجرا نشد.
