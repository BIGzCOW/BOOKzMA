# مشخصات قابلیت: پاک‌سازی یادآورهای تکمیل‌شده

## شناسهٔ ROADMAP

U-03 و F-13؛ پیشنهاد تکمیلی برای یادآورهای مطالعه و مسباک

## چرا

کاربر ممکن است چند یادآور مطالعه یا مسباک در یک روز دریافت کند. پس از تکمیل عادت، پیام‌های باقی‌مانده در چت شلوغ می‌مانند، با اینکه دیگر کاری برای آن‌ها لازم نیست.

## رفتار از دید کاربر

- بعد از ثبت موفق مطالعه در ربات، همهٔ پیام‌های یادآور مطالعهٔ همان روز محلی برای کاربر پاک می‌شوند.
- بعد از تکمیل هدف روزانهٔ مسباک، همهٔ پیام‌های یادآور مسباک همان روز پاک می‌شوند.
- اگر ثبت از خود پیام یادآور انجام شود، آن پیام در handler به نتیجهٔ ثبت تبدیل می‌شود و حذف نمی‌شود؛ پیام‌های یادآور دیگر حذف می‌شوند.
- اگر ثبت از کتابخانه یا مسیر دیگری انجام شود، تمام یادآورهای همان عادت/روز حذف می‌شوند.
- reminderهای آینده و پیام تأیید ثبت دست‌نخورده می‌مانند. تا وقتی هدف مسباک کامل نشده، یادآورهای نوبت‌های باقی‌مانده می‌توانند ارسال شوند.

## اثر روی کل محصول

- مسیرها: scheduler مطالعه و مسباک، ثبت مطالعهٔ دکمهٔ «امروز خوندم»، ثبت صفحات کتاب و callbackهای ثبت نوبت مسباک.
- API: قرارداد فعلی تغییر نمی‌کند؛ ثبت از API همچنان ارسال‌های بعدی را با منطق موجود متوقف می‌کند، اما حذف فوری پیام نیازمند دسترسی Bot API است و فقط در مسیرهایی اجرا می‌شود که Bot موجود است.
- پنل ادمین/آمار: KPI یا action جدید لازم نیست.
- کاربران موجود: هیچ backfill لازم نیست؛ فقط پیام‌هایی که پس از deploy ارسال شوند message ID ثبت خواهند داشت.

## داده و حریم خصوصی

- جدول `reminder_messages`: کاربر، نوع عادت (`reading` یا `mesbak`)، کلید schedule، روز محلی، Telegram message ID و پرچم `cleanup_pending`.
- پیام‌ها حداکثر در محدودهٔ لازم برای retry cleanup نگهداری می‌شوند؛ متن یادآور ذخیره نمی‌شود.
- FK کاربر با cascade حذف حساب دارد؛ پیام‌های یتیم قدیمی پاک‌سازی می‌شوند.

## حالت‌های خاص

- ارسال Telegram و ذخیرهٔ DB اتمیک نیست؛ در crash بین این دو احتمال یک پیام بی‌ردپا وجود دارد، مانند سایر ارسال‌های فعلی.
- بعد از ثبت، ابتدا حذف‌ها به‌صورت پایدار علامت‌گذاری و commit می‌شوند؛ حذف فوری تلاش می‌شود و scheduler پیام‌های باقی‌مانده را retry می‌کند.
- پیام قبلاً حذف‌شده، بیش از مهلت Telegram، یا غیرقابل‌حذف، permanent محسوب می‌شود و reference آن پاک می‌شود تا loop متوقف نشود.
- خطای شبکه/سرور موقت است و `cleanup_pending` را نگه می‌دارد تا retry شود.
- `keep_message_id` که handler آن را به پیام نتیجه تبدیل کرده، از cleanup حذف می‌شود؛ بقیهٔ پیام‌های همان کاربر/عادت/روز pending می‌شوند.
- روز بر اساس timezone همان کاربر محاسبه می‌شود؛ مطالعه و مسباک هرگز پیام‌های یکدیگر را پاک نمی‌کنند.

## امنیت و مجوز

- فقط پیام‌های ثبت‌شدهٔ همان `user_id` و همان نوع عادت پاک می‌شوند؛ شناسهٔ Telegram از DB داخلی می‌آید، نه از callback آزاد.
- متن یا محتوای پیام یادآور در DB جدید ذخیره نمی‌شود.

## خارج از محدوده

- ویرایش یا حذف یادآورهای قدیمی که قبل از deploy ارسال شده‌اند.
- حذف خودکار همهٔ پیام‌های عادی ربات یا تغییر سقف/ساعت ارسال reminder.

## تصمیم‌های باز برای مالک

ندارد؛ حذف پیام‌های دیگر همان روز و نگه‌داشتن پیام ثبت‌شده تأیید شده است.
